# bab — repo card

WHAT: "the door": actor → action → object authorization for agent fleets on OpenFGA, with three verdicts: allow, approve (a human on the owning team says yes), deny (default). A YAML catalogue generates the OpenFGA model; `Door.decide` is the one runtime check, meant to run at tool dispatch.
STATE: main, v0.4.12 (pyproject; bab/__init__.py `__version__` lags at 0.4.9 and nothing reads it: the release tag guard reads pyproject), package name `tenish-bab`. Increment one of docs/design.md (catalogue, model with ceilings, door, syncs, CLI) tagged v0.1.0; increments two and three of docs/design-leases.md (expiring grants, `bab serve`, ledger, AWS minter) are 0.2.0; 0.3.0 adds the room's topology push (`PUT /topology`, agents table, pod identity -> agent) and the release workflow; 0.3.1 gives vendors a kind (cloud vs service), one read permission per cloud service, and a data-plane Deny in every AWS session; 0.3.2 adds GET /identity, POST /probe and DELETE /integrations for a console that connects accounts; 0.4.0 adds organizations (hub role) with accounts (spoke roles) under them, two-hop leases, and account discovery through the hub; 0.4.4 gives an organization one external id and `POST /integrations/{org}/discover`, which probes every member account for the spoke role; 0.4.5 adds the `agents` vendor with `a2a_ask`, `GET /agents/{asker}/talks-to`, and the two lease walls (on_behalf_of refused, no lease on an agent); 0.4.7 adds the Datadog minter (a scoped application key per lease) and the gateway lane `POST /leases/for-agent`; 0.4.9 adds `mcp_read`/`mcp_write` to every Datadog lease so the key works on Datadog's MCP server; 0.4.10/0.4.11 add the GitHub minter (an installation token narrowed to the granted rows' `extra.permissions` and the integration's `spec.repositories`); 0.4.12 makes GitHub three nested levels with labels, lets a child hang under a service connection (one level deep), and resolves a lease asked for by the parent's name to the one child the agent holds (kobo#365). Deployed on one dev cluster through a sibling config repo (bab + OpenFGA, Postgres-backed); CHANGELOG.md from 0.2.0.

GOTCHAS:
- model/example.fga is GENERATED from catalogues/example.yaml by bab/model.py. Never hand-edit; CI and tests/test_model.py both diff it.
- model/example.fga.yaml is the fixture + assertions for `fga model test` AND the demo's `fga store import`. Its users are bare ids (user:alice) while the Okta sync keys users by lowercased email; the fixture is illustrative, not sync output.
- Its grants exceed its ceilings (e.g. atlas configmap_update on a dev project with no ceiling_configmap_update). Legal: ceilings are checked at write time by bab/grants.py `grant`; the fixture is imported, not granted, and Door never checks them.
- Syncs own WHOLE relations: okta owns `member`; topology owns `team`, `owner` and parent-link relations. A topology sync from a partial file deletes every link it didn't produce.
- OpenFgaStore wraps check/list_users/list_objects errors in StoreError (door fails closed), but write/delete/read_all do not: a sync failure surfaces as a raw SDK exception.
- The write gate with pinned assertions (README "every policy change is tested before it lands") is design, not code: nothing here runs assertions on a grant write.
- docs/design.md is a design record: the console, deploy and SDK hook it describes are plans, not code.
- bab is authorization, NOT the approval UX: it returns approvers; posting the plan and waiting for ✅ is the caller's job.
